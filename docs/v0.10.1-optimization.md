# v0.10.1 首轮体积与内存优化

本轮实施：
- 新增 build-android-release.cmd：先静态检查、运行测试，再分别生成 ARM64 Release 与多架构通用 Release。使用单一目标架构构建，不使用 ABI 分包自动增加版本号，两个包均使用 pubspec 的版本号。
- 版本升级到 0.10.1+12；继续使用现有本机调试密钥签名，以保持与之前安装包的覆盖兼容性。Release 是编译模式，不表示已经改用正式分发签名。跨电脑签名一致性仍需验证，密钥不提交仓库。
- 两张门店图转换为宽1280像素的 WebP，打包清单只包含压缩图。原 JPG 留在源码中供备查，不再进入 Flutter 资源清单。
- 门店缩略图限制解码宽度180，大图1280。
- 个人照片保持原数据结构，避免本轮引入数据迁移；同一组件在照片不变时复用解码字节，继续保留160像素缩略图限制。
- 餐品菜单改为 SliverList.builder，按滚动位置创建、释放条目。其他页面尚未全部改为惰性列表。
- 添加菜单懒加载与滚动到末项的回归测试。

实测资源大小：
- community：314062 → 61350 字节。
- shiweifang：196079 → 60544 字节。
- 合计：510141 → 121894 字节，减少388247字节，约76.1%。这是这两张资源图的变化，不是整体 APK 或运行内存的缩减比例。
- 原 v0.10.0 Debug APK 基线：156144611 字节（约148.9 MiB）。

验证状态：
- 已查看压缩门店图片；构建脚本通过 PowerShell 语法解析。
- 2026-10-18 用户本机构建日志已核对：静态分析无问题，43项测试全部通过，两种 Release APK 构建成功。尚无真机运行内存数据。
- 用户运行 build-android-release.cmd 后，日志位于 logs/android-release.txt；生成文件在项目上一级：eat-what-android-arm64-release.apk、eat-what-android-universal-release.apk。检查日志后再比较实际大小及签名，不沿用旧版42项通过结论。

参考：
- https://docs.flutter.dev/deployment/android
- https://api.flutter.dev/flutter/widgets/SliverList/SliverList.builder.html

构建后核验（2026-10-18）：
- ARM64 APK：18949929 字节（18.1 MiB），相对旧 Debug 包减少87.9%。Flutter引擎和应用原生库仅包含arm64-v8a。
- 通用 APK：53720595 字节（51.2 MiB），减少65.6%。包含三种架构的Flutter引擎和应用库。
- 两包均为 local.eatwhat.campus，版本0.10.1，versionCode12；apksigner验证通过，签名证书与旧版一致。实际手机覆盖安装和数据保留尚未验证。
- 以上为安装包体积对比，不代表运行内存下降相同比例；主要收益包含Debug改为Release及架构精简。
