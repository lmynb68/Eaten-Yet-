# 菜单重建

当前核准基线为第 10 版、10 家店、1,735 项菜品，其中麦港餐厅 101 项。

在项目根目录运行：

```shell
python docs/rebuild_catalog.py --check
python scripts/test_catalog_rebuild.py
```

`--check` 在临时目录中重建，检查结果与 `assets/official.json` 完全一致，不写回文件。重建入口依次使用冻结底库、各餐厅整理脚本、餐次分类和麦港数据。`docs/catalog-maigang.json` 保存了用户 2026 年 11 月 4 日照片对应的已核准数据；早餐、午餐和晚餐范围随记录保留。麦港录入放在旧餐次分类之后，避免早餐被默认改为午晚餐。

需要正式写回时运行 `python docs/rebuild_catalog.py`。它先在临时目录执行全部录入脚本，再检查：版本不倒退、编号唯一、餐厅关联存在，以及当前店铺、菜品、食材和套餐不被遗漏或改写。新增记录需要提升菜单版本。检查通过后才在目标目录写临时文件，并原子替换正式文件；内容一致时不改动原文件。导入脚本产生的临时核对表和旧版本快照不会写回项目。

如果现有价格或其他记录与重建来源不一致，脚本会停止并报告差异。请先核对照片和整理来源，将已核准的变更同步到源数据、正式菜单及菜单版本，再执行检查；不要绕过保护强制覆盖。餐厅单独录入脚本供隔离重建使用，日常维护从 `rebuild_catalog.py` 进入。

麦港整理函数只处理内存中的数据，直接运行 `docs/import_maigang.py` 会拒绝执行并提示使用重建入口，避免绕过正式菜单的保护检查。新增记录也会检查必填字段、价格、分类，以及店铺和食材关联。

回归覆盖完整重建和重复重建、漏掉麦港、同版本漏店、既有价格变更、未纳入来源的新菜品、残缺来源、直接运行麦港脚本、无效新增数据、只检查不写回、替换失败，以及执行期间发生的文件修改。所有写入均在临时副本中完成。
